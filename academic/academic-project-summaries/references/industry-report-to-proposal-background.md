# 将产业白皮书/市场报告整合进 Proposal 背景

适用场景：
- 用户给出行业白皮书、市场研究、政策报告、园区/资本生态报告
- 用户要求“作为研究背景加入 proposal / 立项依据 / 研究意义”
- 项目本身是平台型、方法型或产业导向型课题

目标：
不是把报告内容搬进 proposal，而是把行业材料压缩为能支撑项目“为什么现在必须做、为什么这个平台有意义”的背景论证。

## 推荐写法

优先放入：
- 立项依据
- 研究背景
- 研究意义

不优先放入：
- 研究内容
- 技术路线
- 创新点
- 预期结果

原因：
行业白皮书提供的是宏观必要性和产业约束，不是项目内部实验设计证据。

## 建议抽取的四类信息

### 1. 产业链结构
典型表达：
- 上游使能技术
- 中游平台赋能
- 下游产品落地
- DBTL（Design-Build-Test-Learn）闭环能力

用途：
把用户项目定位到正确层级。若项目本质是方法平台，优先写成中游平台能力，而不是单一产品开发。

### 2. 产业趋势
可抽取：
- 单点技术突破正在转向平台化竞争
- 决定竞争力的不再只是单产品，而是设计、构建、测试、学习与转化的协同效率
- 政策、资本、园区、科研平台正在加速聚集

用途：
解释“为什么现在做这个平台具备时机意义”。

### 3. 中国与海外差距
优先抽取：
- 自动化/高通量测试
- 数据库与 AI 设计工具
- 平台复用能力
- 工程转化效率
- 放大生产、批间一致性、监管约束

用途：
把宏观短板转译为项目切入点。最有效的句式通常是：
“产业实践表明，当前短板不在概念提出，而在于______。”

### 4. 与本项目的直接对应关系
必须写清楚：
- 这份行业背景为什么说明当前迫切需要用户的项目
- 项目解决的是产业瓶颈中的哪一段
- 项目更像“单产品优化”还是“平台能力建设”

## 推荐句式

### 平台型项目常用句式
- 合成生物学正在由单点技术突破走向平台化与产业链协同竞争。
- 下一阶段竞争将更多体现为平台效率竞争，而非单产品概念竞争。
- 决定竞争力的关键不只是某一产品能否做出来，而是能否形成设计—构建—测试—学习与转化衔接的平台能力。
- 本项目所聚焦的方法平台，正对应当前产业瓶颈中的关键缺口。

### 收束到本项目的句式
- 因此，从学科演进与产业发展两个层面看，建立______平台具有明确必要性。
- 尤其在______场景中，如果不能解决______问题，再先进的设计模型也难以转化为实际生产力。
- 本项目并非单一靶点优化，而是针对产业共性瓶颈提出的平台化解决思路。

## 不推荐写法

避免：
- 大段照抄行业报告目录、市场规模数字、企业名单
- 把产业报告写成“读书笔记”式综述
- 用产业报告直接证明实验机制
- 让行业背景引出新的并列方向，冲淡 proposal 主线

## 一个常用压缩骨架

```markdown
### 研究背景

[第一段] 学科/技术背景：当前方法为什么重要。

[第二段] 应用/工程背景：在实际系统中为什么现有策略不够。

[第三段] 产业背景：行业正在从单点突破走向平台竞争，当前瓶颈集中在哪些能力。

[第四段] 回到本项目：本项目对应产业关键缺口，因此具有科学与产业双重意义。
```

## 本次会话提炼出的具体可复用点

- 对平台型 proposal，行业白皮书最有价值的是“平台化趋势”和“中国产业短板”，不是具体公司列表。
- 对 binder/AI/工程化项目，最适合借行业白皮书强调的是：自动化、高通量测试、数据工具和平台复用能力不足。
- 整合时应把项目定位为“平台效率提升”或“闭环能力建设”，而不是新增一个市场分析章节。
