- 注重文档专业性、简洁性、规范性（markdown 格式）
- 经常撰写项目概述等申报材料
- 偏好精炼、逻辑清晰的学术语言，重视创新性和专业性

## 核心偏好

### 格式规范
- 最终 deliverable 为权威 markdown 文件，保存在项目路径中
- 不接受对话痕迹、装配说明、内部溯源表述
- 禁止短语："从原国家自然科学基金正文材料进一步梳理可见"、"原面上项目正文…现整合如下"、"现整合如下"
- 终稿读作独立提交文本

### 语言规则
- **基金申报 / NSFC**：中文
- **manuscript / NBT**：英文
- **255 字中文摘要**：一段话，覆盖背景/目标/内容/创新/价值
- 每句话承载一个核心信息块
- 压缩优先级：删套话 → 合并近义 → 缩短背景 → 合并成果+意义

### 结构偏好
- 偏好 NBT 级三段式（Platform + Strategy + Application），不偏好五段并列 aim
- 应用方向不平均分配：选 1-2 个主应用深挖，辅助模块（如 sensor）定位为 feedback readout
- 重视 gap-analysis：明确"现有方法有什么问题 → 我们为什么需要新方法 → 新方法的优势是什么"
- 重视参数对比表格：同时呈现支持性与边界条件

### 实验设计偏好
- 每个关键 claim 应有定量验证设计
- 必须有 benchmark（与现有方法的头对头比较）
- 必须有消融实验（ablation study）
- 必须有阳性/阴性对照矩阵

### 摘要写作（255 字限制）
- 严格控制在 255 字以内
- 默认一段话
- 覆盖：背景 → 目标 → 内容 → 创新 → 价值
- 每句只承载一个核心信息块
- 如超字数，按此顺序压缩：删修饰语 → 删背景 → 压缩成果表述

### 方法学对比交付骨架
```markdown
## 总体判断
一句话定位

## 一、方法A主要缺点
## 二、方法B主要缺点
## 三、共同局限
## 四、压缩版总结（可直接粘贴）
## 五、一句话结论
```
