# JSON-first three-section academic briefing

Condensed session guidance for template-derived scientific briefing decks when the user wants:
- JSON first
- exactly three macro sections: `研究背景 / 研究思路 / 研究方案`
- short on-screen bullets
- keyword emphasis inside PPT runs

## Durable workflow
1. Build a JSON outline first and treat it as the authoritative narrative spine.
2. Keep the whole deck inside the three macro sections, even if a section spans multiple slides.
3. Organize each section by `问题 / 方法 / 效果`.
4. Compress each bullet to roughly one short Chinese clause (~20 characters).
5. In the PPT, render the lead keyword as a separate run with bold + red styling; keep the rest of the bullet in the section color.

## Specific lesson from this project class
The `研究背景` slide can hide two different backgrounds that should not be merged:
- dry-lab / protein-design bottlenecks
- metabolic-control demand for new tools

A strong split layout is:
- Left block: current dry-lab problems
- Right block: why metabolic regulation needs protein-level tools

## Protein-level writing vs gene-level manipulation
When the user highlights protein-level `写入`, make the advantage explicit:
- freer control
- reversible intervention
- faster timing than gene-level manipulation

## Example short bullets
- `候选`虽多，胞内转化率偏低
- `传统`验证周期长且成本偏高
- `蛋白写入`比基因操作更自由
- `可逆`且写入时间更快

## Why this matters
This format improves projector readability, oral delivery rhythm, and template fit. It also prevents background slides from becoming vague summaries that hide the real motivation split.
