# 专利总结稿 → 可审计引用表 workflow

适用场景：
- 用户已经要到一版专利总结/限制因素总表；
- 进一步要求 “with cite / reality 专利内容 / audit version / A 版 / 可审计引用表”；
- 任务对象是 `/home/qiao/qiao_design/e_coli_model/5000万专利申请全量数据1985-2025` 这类超大专利库。

## 目标交付
输出一个项目路径下的中文 markdown 审计表，至少包含：
1. 专利号
2. 标题
3. 申请年份
4. 关联氨基酸
5. 关联限制因素
6. 摘要证据句
7. 本地回查位置（`patents_YYYY.tsv` + `line_no` + `row_id`）
8. 核验状态（已回查 / 未回查到）

## 推荐顺序
### Step 1. 先做主题 summary，再做 audit
如果用户先要总结：
- 第一版可先输出“20种氨基酸覆盖表 + 限制因素总表”；
- 但必须明确这是 summary 版，不等于逐条审计版。

### Step 2. 从 summary 成稿中抽取全部专利号
- 直接从 markdown 成稿中提取全部 `CN...` 申请号；
- 去重后形成唯一专利号集合；
- 同时保留每条专利号在原 summary 中对应的上下文：
  - 关联氨基酸
  - 关联限制因素

### Step 3. 逐条回查本地年分片 TSV
对每个申请号：
- 用 `CNYYYY...` 前四位定位 `中国专利数据库_llm_retrieval/by_year/patents_YYYY.tsv`；
- 在该 TSV 中做完全一致的 `app_no` 匹配；
- 优先把 TSV 结果作为审计引用的本地落点。

原因：
- 年分片 TSV 天然保留 `申请号/标题/摘要精简/主权项精简/line_no/row_id`；
- 做“引用可核验表”时，比只给概括性总结更稳。

### Step 4. 摘取证据句时的规则
- 优先取 `摘要精简`；若摘要过短，再补 `主权项精简`；
- 证据句必须是能直接支撑结论的事实句，不要再加工成新的推断；
- 常用事实优先级：
  1. 菌株/底盘
  2. 关键工程改造
  3. 产量/得率/转化率/滴度
  4. 低氧/硝酸盐/氮同化/外排/副产物/工艺窗口等限制因素信号

### Step 5. 审计表中要显式标注证据边界
必须写清：
- 哪些是“已回查到的本地记录”；
- 哪些只是 summary 中出现、但本地检索层暂未回查到；
- 对像 L-天冬酰胺 这种数据缺口，要明确写“未检出足够可靠的原核发酵生产专利证据”，不能拿酶生产或衍生用途替代。

## 输出建议
### 交付件 1：完整 audit 表
适合附录/内部底稿，保留全部已引用专利。

### 交付件 2：按限制因素汇总的已核验专利号
把每类限制因素压缩成 5–8 条高价值专利，适合正文使用。

## 常见坑
1. 不能把“真实专利总结”误当成“已完成逐条核验”。
2. 不能用营养添加、化妆品、饲料配方中的氨基酸名词命中，冒充“原核发酵生产目标氨基酸”。
3. 不能把“酶生产”替代“氨基酸本体生产”。
4. 不能只给专利号，不给本地回查位置；否则不可审计。
5. 用户要求“reality 专利内容”时，必须优先保留专利原始事实句，而不是只写专家解释。
